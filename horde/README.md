# 横板射击 · 割草（horde/）

用解包出来的真实素材做的可玩 Demo：

- **场景**：只用清单里的**美术背景层**（`scenes/Art_*` 9 个场景共 62 张背景），按原游戏 1080 设计视口等比缩放
- **玩家**：`gunner/nanzhu_gunner.json`（注入了持枪骨骼 / IK / 上半身动画集）
- **敌人**：`duke` 等角色骨架，**空手近战**（素材里没有任何持枪敌人）

打开：`python -m http.server 8766 --bind 127.0.0.1`（仓库根目录）→ http://127.0.0.1:8766/horde/index.html

## 操作

| 键 | 作用 |
|---|---|
| `A` `D` | 左右移动 |
| `Shift` | 疾跑 |
| `空格` / `W` | 跳 |
| 鼠标 | 瞄准（准星决定枪口朝向，身体会跟着转身） |
| 左键 | 射击（30 发弹匣，全自动） |
| `R` | 换弹 |
| `F` | 近战 |
| `P` | 暂停 |
| `回车` | 波次间隙立即开下一波 |

## 玩法

- 敌人从画面两侧涌入，追击 → 前摇 → 扑击；被打中会击退、溅血、屏幕震动
- 一波清空后 2.6 秒自动进入下一波，敌人数与血量随波次增长
- 每 5 波出 **BOSS·妹妹**（BOSSmeimei，118 骨，3 页贴图）
- 玩家倒地 2.4 秒后满血复活，重打本波
- 连续击杀有连杀计数（2.2 秒内不中断）

右侧面板可调：背景场景（美术背景层 9 选 1）+ 底图/叠加/前景三层（只能从当前场景里挑）、镜头远近、地面开关、同屏敌人上限、敌人速度、玩家伤害、骨骼/判定框显示、屏幕震动。

## 结构

```
common.js   Spine 资源加载器：多页图集、UV 修正、按附件顶点量包围盒 / 脚底
player.js   玩家：分层轨道动画 + 程序化瞄准 + 两骨 IK + 抵肩 + 开火/换弹
enemy.js    敌人：类型表 + AI 状态机（spawn/chase/wind/attack/hurt/dead）
game.js     波次、子弹命中、粒子与震动、背景视差、HUD
```

三张画布叠放：`#bg`（2D 背景）→ `#gl`（WebGL 角色）→ `#fx`（2D 前景与特效）。

## 实现要点

### 敌人为什么是程序化的

角色自带动画只有 `idle / walk / run`（duke 连 attack、death 都没有），所以：

- **攻击**：前摇用 root 骨骼后仰，扑击用前冲 + 正弦摆动，命中判定在挥击 35% 处触发
- **死亡**：无死亡动画时 root 旋转 88° 倒地 + 落地反弹 + 淡出；有 `death`/`blood_death` 的角色优先用自带动画
- **走路/跑步**按速度调 `timeScale`，避免脚滑

### 尺度统一

各种角色骨架单位不一致（包围盒高度 1700～3300），所以每个角色都用
`scale = 目标身高 / 包围盒高度` 反推缩放，自动统一到同一画面尺度。
包围盒按**附件顶点**算——直接用骨骼端点会被头发/飘带拉高（duke 能测到 2400+），
而 spine 的 `SkeletonBounds` 只统计 `BoundingBoxAttachment`，角色身上根本没有，两者都不能直接用。

### 背景只能挑美术背景层

清单里的 19 个场景分三类：`Art_*`（9 个）是**纯背景层**（根节点 `2DEnvironment_Art`、零碰撞体），
`designer_*` 是玩法层（背景和道具/柱子/角色节点混在一起），`00_main` 是 UI 常驻层。
后两者的图当背景会穿帮，所以代码里按场景白名单过滤，只留 `Art_*`。

同一场景里的多张图是**不同房间 / 分区**，不是一个画面的远中近分层（01_Art_0 是 `street_*` 街道长卷，
10_Art_b 是 `BG_Hall_Bsite_*` 大厅卷加 `Room*` 房间整版）。不透明底图一铺就盖住下层，
所以默认只铺一张底图，另两层留给用户按需叠加。

### 尺度：世界缩放和背景缩放必须分开

**背景画在屏幕空间**：1 图像像素 = 1 设计像素，`bgSc = H / 1080`，**不随相机变**。
**世界里的东西**（角色、敌人、粒子、子弹）走 `viewSc = H / VIEW_H`，`VIEW_H` 是可视世界高度。

这两个尺度必须分开。拉近镜头时如果背景也跟着放大，人物和背景同比变大，
「人物相对背景太小」根本没解决，背景还白白被拉糊。所以只有角色变大、背景纹丝不动：

实测（1920×1080，`street_BG_9` 原图 8192×1014，钩住 `drawImage` 读实参）：

| `VIEW_H` | 角色屏幕高 | 背景绘制矩形 |
|---|---|---|
| 1080 | 190 px | `y=0 w=8192 h=1014` |
| 680（默认） | 302 px | `y=0 w=8192 h=1014`（**完全相同**） |
| 420 | 489 px | `y=0 w=8192 h=1014`（**完全相同**） |

背景始终是 1:1，不糊；变的只有角色。

角色占屏恒为 `190 / VIEW_H`（与窗口大小无关）。改 `VIEW_H` 要同步这几处，
漏一处就会出现「角色放大了但世界量还按旧比例算」的错位：

1. 相机 `zoom = 1 / (viewSc * dpr)`
2. `w2s` 映射（`s2w` 走 `camera.screenToWorld`，自带 zoom）
3. 相机 `camY = (groundY - H/2) / viewSc`
4. 屏幕相关的世界量：玩家活动范围 `W*0.62/viewSc`、刷怪距离 `W/2/viewSc`、震动幅度 `/viewSc`、敌人 AI 的 `G.viewW`
5. 背景的**视差平移**用 `bgSc` 而不是 `viewSc`（平移相对背景设计像素，不相对世界单位）

背景 PNG 是按原游戏 **1080 设计视口**画的（房间整版一律 1080 高，长卷 530/827/936，条带 111/281/331）。
**不要**按每张图自身高度拉满屏幕——那样 8192×530 的长卷被放大 2 倍、2048 高的竖版被压扁一半，
比例全错（同一个角色在不同背景上会忽大忽小）。

竖直定位：整版/长卷的地板线画在图内 `0.76×1080` 处、条带底边就是地平线，
让这个高度落在屏幕 `groundY = 0.76H`，即 `y = groundY - hz * bgSc`——与相机远近无关，
所以调 `VIEW_H` 时地面不会漂，角色脚底和背景地板线始终重合。

### 转身时手臂为什么会拧（以 gunner/game.js 为基准）

玩家模块与 `gunner/game.js` 保持同源，转身不拧臂靠三件事，缺一不可：

1. **顺序**：`scaleX`（镜像）必须在任何世界角计算之前写入。放在 `solveArm()` 之后的话，
   IK 拿着上一帧的朝向解算，转身那一帧手臂就拧成一团。
2. **纸片翻转**：翻面时 `scaleX` 在 0.14s 内从旧朝向收缩过 0 再展开成新朝向，镜像不硬切
   （过 0 的那一两帧世界矩阵退化，但角色纸一样薄，看不见）。
3. **肘部选解**：两骨 IK 有两个解（肘在肩的两侧），用「肘部世界 y 更低」来选并带迟滞，
   两个朝向下肘都朝下。**不要**用固定符号、更不要按朝向翻符号——朝右恰好朝下、朝左就甩到头顶。

实测：两个朝向来回翻转，每 25ms 采样，双手到握点偏差稳定 0/2px（翻转过 0 处有 1 帧不可见尖峰），
肘部低于肩 195–269 骨架单位，两侧一致。

### 命中

子弹按 1750px/s 步进采样，与敌人 AABB 做线段相交；命中给击退、顿帧（hitstop 28ms）、血粒子。
割草手感主要靠：击退 + 顿帧 + 震动 + 连杀计数 + 大量血粒子。

## 已知问题 / 后续

- 敌人没有受击与死亡动画，全部程序化，观感偏"被推开倒地"
- 程序化地面（`groundY = 0.76H`）只对「地板线画在 `0.76×1080`」的整版图精确对齐，长卷/条带场景会有偏差
- Boss 只有第 5/10/15… 波，且它的 `attack_loop` 等动画尚未接入 AI（当前仍用通用前摇扑击）
- 没有掉落物、技能、多武器
